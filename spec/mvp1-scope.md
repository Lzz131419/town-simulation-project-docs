# 雾河镇 MVP1 范围与模块清单

> 课程第7周；范围级文档，版本2.0，2026-11-18。模块细节分别在五份 Spec 中。

## 一、名词说明
MVP1 是最小可行版本的范围；模块是其中有独立输入输出的组成单元。每个纳入模块均有独立 Spec，不能把整个系统塞进一份模块文档。

## 二、MVP1一句话演示路径
载入小镇 → 导入1名授权人物 → 推进并观察生活 → 触发短缺、表决维修水井 → 导出恢复并复现30天结果。

固定模板30名生成居民，导入后31名；day=0开始，30次推进到day=30。唯一议案 repair-well-01 在初始化时 OPEN；无需先实现故障系统或自由提案。只模拟一个本地世界，不依赖登录、数据库或模型服务。

| 模块 | 是否MVP1 | 端到端角色 | 负责人 | 依赖 |

| AI对话与模型行为选择 | 否 | MVP2候选 | 不分配当前任务 | 服务端与成本方案另评审 |
| 多模板/更多人物/自由议题 | 否 | MVP2候选 | 不分配当前任务 | MVP1强评审后再拆 |
| 账号/云同步/多人协作 | 否 | 后续在线版 | 不分配当前任务 | 独立架构决策 |

此处依赖是职责依赖；程序导入方向以 [架构](../docs/architecture.md) 为准，禁止 M2–M5 反向引用 M1。

## 四、可演示成果与验收门槛
- 30名生成居民+1名导入人物，共同参加规则结算；导入不增加资金总量。
- 至少一种生产、一次集市交易、一次广场关系变化；水井/广场提供两类公共与娱乐设施。
- 一次轻度粮食短缺可追踪库存减少；一次维修议案可核对票数、120镇币成本、清水+30和信任+5。
- 30次成功推进无负库存/负资金，个人与公库资金总和恒定（维修费明确记入外部支出）。
- 快照恢复后继续运行与不中断运行得到相同规范化状态；损坏快照拒绝且不覆盖当前状态。
- 正式页面显示数值和来源事件；本轮文档完成不代表这些业务验收已通过。
