## 1. 目的

本文回答“MVP1 第一版做到哪一步”。模块内部规则、用户故事和验收标准写入对应模块 Spec，本文不重复实现细节。

## 2. MVP1 目标

创建者可以在一个固定历史背景下运行一座可解释的小镇，观察居民生计、社交和公共决策如何相互影响，并通过快照复现主要结果。

本项目不是真实社会预测器。MVP1 的目标是形成可测试的软件闭环，为后续模型驱动居民和历史情景扩展提供稳定底座。

## 3. 目标用户

- **创建者**：载入场景、推进时间、导入授权数字人物、触发受控事件、执行公共决策和导出结果。
- **观察者**：查看小镇总览、居民详情、资源变化和事件原因。
- **数字人物本人**：在导入前确认允许进入模拟的字段。

## 4. 最短端到端路径

1. 创建者载入“雾河镇·春旱”固定场景。
2. 场景生成 30 名规则居民，并包含农田、水井、集市、中央广场和居民住宅。
3. 创建者导入 1 位已获授权的数字人物，使可见居民总数为 31 人。
4. 创建者推进 1 天，查看至少 1 位居民的工作、消费、社交或娱乐结果。
5. 水井出现机械故障后，系统将维修议题列入公共事务。
6. 居民根据当前需求、信任和关系形成立场并投票；创建者执行通过的议案，查看公库、清水和信任变化。
7. 创建者触发轻度粮食短缺，查看粮食库存、居民需求和事件时间线。
8. 创建者推进至第 30 天，导出快照；重新导入后确认种子、版本、主要库存和事件记录恢复。

路径中的 8 个步骤是演示顺序，不是 8 条必须同时展示在不同页面上的独立功能。

## 5. 成功标准

MVP1 在以下条件全部满足时通过：

- 固定场景初次载入时包含 30 名规则居民，数字人物导入成功后可见总人数为 31。
- 系统可以连续推进至少 30 个模拟日。
- 每名活跃居民至少有一条当日行动结果；居民详情能够展示精力、饥饿、个人余额、关系和近期事件。
- 生产、消费或公共决策至少有一项可以核对到具体主体、规则版本和结算结果。
- 粮食短缺会导致至少一项居民或库存状态变化，并产生可追踪事件。
- 公共决策包含居民立场、计票、执行条件和执行结果。
- 相同场景版本、规则版本和随机种子的两次运行产生相同关键结果摘要。
- 合法快照可以恢复；损坏、旧版本超限或缺少字段的快照被拒绝，且不覆盖当前状态。
- 正式页面不调用 AI 模型，不请求真实个人数据，不包含任何密钥。

## 7. 跨模块契约

### 7.1 稳定标识

- `townId`、`agentId`、`facilityId`、`proposalId` 和 `eventId` 在单次时间线内稳定且唯一。
- 显示名称可以重复，业务逻辑不得使用显示名称代替 ID。
- 事件、快照和验收夹具只能引用稳定 ID。

### 7.2 时间

- MVP1 的时间单位为“天”。
- 初始场景从第 1 天开始；一次单步推进产生第 2 天及相应行动结果。
- 所有模块使用同一个 `day` 和事件序号，不各自维护不兼容的计时器。

### 7.3 数值范围

- `energy`、`hunger`、`waterNeed`、`trust` 和关系值范围为 0—100。
- 库存、余额和公库不得为负。
- 所有越界输入必须被拒绝或限制在声明范围内，并留下对应错误事件。

### 7.4 结果与错误

模块操作返回统一结构：

```text
Result {
  ok: boolean
  data?: object
  error?: {
    code: string
    message: string
  }
  events: Event[]
}
```

错误标识用于测试和界面提示。界面可以翻译展示文案，但不得改变错误标识。

### 7.5 事实与解释

- 程序计算和状态变化属于事实。
- 面向用户的叙述属于解释。
- 关键数值只能由规则计算；解释文本不能反向覆盖库存、余额、计票或状态。

## 8. 演示配置

| 项目 | MVP1 默认值 |
| --- | --- |
| 场景 | 雾河镇·春旱 |
| 规则居民 | 30 |
| 数字人物 | 最多 1，导入后总人数 31 |
| 初始日期 | 第 1 天 |
| 运行时长 | 至少 30 天 |
| 资源 | 粮食、木材、清水、镇公库、居民个人余额 |
| 设施 | 河畔农田、老水井、雾河集市、中央广场、居民住宅 |
| 公共议题 | 维修老水井 |
| 外部冲击 | 轻度粮食短缺 |
| 随机种子 | 由场景配置固定并写入快照 |

具体库存、价格、工资和阈值由 `ScenarioConfig` 保存。实现可以调整数值，但不得把硬编码页面数值当作隐含规则。

## 9. Non-Goals

MVP1 明确不做：

- AI 模型、自由文本对话、模型自主决策或自动生成人物经历。
- 真实历史数据导入、历史准确性评分或反事实分支对照。
- 玩家附身、第一人称移动或多人实时互动。
- 注册登录、服务端数据库、云同步和权限系统。
- 自动生成公共议题、完整议会制度、多轮辩论和竞选活动。
- 复杂市场议价、贷款、利息、金融资产或完整供应链。
- 疾病传播、死亡、出生、战争和跨城镇迁移。
- 地图编辑器、3D 场景和自由寻路。
- 从个人主页抓取资料、人脸克隆和真实人物行为预测。

## 10. 范围变更

任何新增模块、扩大人口、增加 AI 调用或将非目标纳入 MVP1，必须：

1. 新建 Issue，说明用户价值和不增加的取舍。
2. 更新本文档和受影响模块 Spec。
3. 补充至少一条可判定 AC。
4. 重新评估第 11 周交付风险。
5. 由非作者复核后进入实现。
