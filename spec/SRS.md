# 第一阶段软件需求规格

## 1. 目的与范围

本文定义数字居民小镇模拟系统第一阶段的可验证需求。目标是让用户创建并运行一个小型小镇，观察生计、社交和公共决策过程，并从日志与快照中复盘状态变化。

## 2. 用户场景

- 创建者选择普通小镇、粮食紧张或战后重建模板，调整人口、库存、设施、文化和制度。
- 创建者导入少量数字人物并生成规则约束的居民。
- 观察者推进模拟时间，浏览总览、居民详情和事件时间线。
- 居民围绕公共资源提出议题，经过讨论和投票/制度决策后执行政策。
- 创建者导出配置与快照，另一位组员可用相同配置复现演示。

## 3. 功能需求

| ID | 需求 | 验收依据 |
| --- | --- | --- |
| FR-01 | 系统应创建、校验、保存和复制小镇初始配置。 | 保存配置后可重新载入并启动模拟。 |
| FR-02 | 系统应支持居民档案、关系、需求、资源和记忆摘要。 | 居民详情能展示身份、近期活动、关系和记忆摘要。 |
| FR-03 | 系统应支持 1–3 个导入数字人物及规则约束的随机居民。 | 演示中至少导入 1 人并生成至少 10 人。 |
| FR-04 | 系统应通过规则推进需求、工作、生产、消费和交易。 | 资源与余额变化可追溯到具体行动。 |
| FR-05 | 系统应支持社交互动并更新信任、亲密、尊重或冲突等关系维度。 | 至少一段关系变化出现在居民详情和事件日志。 |
| FR-06 | 系统应支持公共议题、讨论、投票/决策、政策生效和结果记录。 | 完成一次“维修水井”或同类议题闭环。 |
| FR-07 | 系统应支持可配置事件及其影响链。 | 触发轻度粮食短缺后可查看库存及影响记录。 |
| FR-08 | 系统应支持暂停、恢复、单步推进和快照/时间线导出。 | 相同配置与规则版本可重复启动并对照结果。 |
| FR-09 | 系统应展示小镇总览、居民详情和事件时间线。 | 用户可定位某位居民的工作、消费、关系和行为记录。 |

## 4. 模拟规则与模型边界

程序负责时间推进、资源库存、余额、产量、设施容量、投票计数和权限。模型可协助解析人物资料、生成自然语言内容、摘要记忆、排序候选行动和解释事件。模型输出必须校验结构、动作许可和输入范围；失败时采用规则默认行为。系统记录必要的模型版本、耗时和结果摘要，不记录密钥。

## 5. 非功能需求

- **可复现性**：配置、规则版本、随机种子（若采用随机过程）和快照应可保存。
- **可解释性**：关键状态变化可关联触发原因、规则和行动记录。
- **安全与隐私**：模型最小化数据访问；密钥仅在服务端管理；个人字段按授权公开。
- **可恢复性**：事件可暂停、快照可恢复；重大事件有强度参数和影响范围。
- **可控成本**：模型调用可限额、复用摘要，并优先在必要事件触发时调用。

## 6. 建议验收场景

建立 30 人小镇，配置农田、水井、集市、广场和一种投票制度；导入 1 个数字人物并随机生成至少 10 名居民。推进模拟，展示居民工作、消费、社交和娱乐轨迹；提出“维修水井”议题并展示从讨论到政策生效的闭环；触发轻度粮食短缺并查看库存、价格/资源压力、情绪或关系影响；最后导出时间线和快照并复现。

构想文档还提出连续推进至少 30 个模拟日的成功标准。建议将其作为运行稳定性验收，与上述较短的课堂演示脚本分开记录。

## 7. 待确认事项

- 时间单位采用天还是小时；单步内行动顺序和并发规则。
- 第一阶段设施、资源种类、人口上限和制度选项。
- 前端、后端、数据库及模型服务的最终选型。
- 首位数字人物可用字段、授权范围和脱敏方案。
- 关系维度与需求指标的取值范围、更新公式和默认参数。
