# 模块Spec：M2 居民生活、生计与社交

> 版本2.0；2026-11-18；负责人：李展博；状态：本地重建，待团队评审。

## 摘要
用确定性整数规则结算工作、食物/清水消费和广场关系。数字人物与生成居民完全共享算法；M2返回候选状态与事实，不直接更新DOM或全局状态。

## 用户故事
- **M2-US-1：理解生计账本**。作为观察者，我想查看生产和消费差额，以便知道资源与资金去了哪里。
- **M2-US-2：观察关系与稳定性**。作为验收人员，我想查看社交和连续运行结果，以便核对模拟是否可解释且守恒。

## 验收标准（Given/When/Then）

### M2-AC-01：工作、休息与工资边界（M2-US-1）
```gherkin
Given 农夫energy=20、公库≥2；另设energy=19和公库=1的独立夹具
When 按FR-02结算工作
Then energy=20的农夫粮食+4、energy-10、个人cash+2、公库-2；energy=19者改为休息energy+20、不产出不领工资；公库1时正常劳动但只发1并记录WAGE_SHORTFALL差额1，所有金额非负。
```

### M2-AC-02：消费阈值与缺货资金异常（M2-US-1）
```gherkin
Given 需求增长后hunger=50，粮价2，居民cash=2且food=1；另测hunger=49、food=0、cash=1、水库存0
When 执行一次消费阶段
Then 主夹具food=0、cash=0、公库+2、hunger=10；49不购买；food=0记录FOOD_OUT_OF_STOCK，cash=1且food>0记录INSUFFICIENT_PERSONAL_FUNDS，均不扣款不减粮；waterNeed≥70且有水则水-1、waterNeed减40；达到阈值但库存0时记录WATER_OUT_OF_STOCK且数值不下降，低于70不取水且不报缺货。每居民每日最多各消费1单位。
```

### M2-AC-03：社交容量、上限和关闭（M2-US-2）
```gherkin
Given 广场开放容量10，至少2名energy≥5且hunger<80的居民，关系trust=99、affinity=99；另测关闭/容量0/只有1人
When 按稳定ID选前10名合格居民并两两配对
Then 每对双向trust+1、affinity+2并上限100，每人energy-5，生成一条SOCIAL_INTERACTION；一人一天最多参与一次。设施关闭或容量0不改变关系，记录FACILITY_UNAVAILABLE；不足2人记录SOCIAL_SKIPPED，不凭空生成对象。
```

### M2-AC-04：30日不变量与确定性（M2-US-2）
```gherkin
Given 固定场景、种子、同一操作序列，30或31名居民；一个对照夹具包含energy=100、hunger=100
When 连续推进30天并检查每日提交后的全量状态
Then 资源/cash/treasury均为非负安全整数；energy/hunger/waterNeed/关系均在0..100；需求增长不越过100。sum(cash)+treasury+externalSpent恒等于初始1600；相同输入两次逐日结果完全一致，每居民每日至少一条行动记录。
```

## 功能需求
- **M2-FR-01（US-1）**：默认居民energy=70、hunger=30、waterNeed=30、cash=20；10名farmer、10名waterWorker、10名resident。导入人物默认cash=0。所有需求增长：hunger+20、waterNeed+20，截断到100。
- **M2-FR-02（US-1）**：energy≥20才劳动；farmer产粮4，waterWorker产水4，energy-10、应发工资2；resident不产出、不领工资，执行休息energy+20。energy<20的任何职业休息+20。工资按min(2,treasury)支付，差额记录WAGE_SHORTFALL；产出不因工资短缺撤回。
- **M2-FR-03（US-1）**：先为全部居民结算工作，再结算全部居民消费。居民顺序是稳定ID升序列表，从本日PRNG产生的offset起循环访问；工作与消费共用这个顺序，不额外抽随机数。先检查粮食库存、再查余额；粮价2，饥饿≥50才买1份，hunger减少40。取水阈值waterNeed≥70，免费且每日最多1单位，waterNeed减少40。余额从居民转给公库，不凭空创造货币。
- **M2-FR-04（US-2）**：广场活动在消费后执行，按ID升序选人，两两配对；初始所有居民关系（含自身表决引用）trust=50、affinity=50。双向关系对称；自关系不参加社交。未参加活动者不额外加精力。
- **M2-FR-05（US-1/2）**：每次产出/工资/消费/休息/失败/关系变化写入明确差额和规则版本。行动拒绝发生于一个最终成功提交的tick内，属于业务事实；整个tick失败则全部这些事件随副本丢弃。
- **M2-FR-06（US-2）**：短缺时不死亡、不迁移；展示hunger≥80为饥饿警告，waterNeed≥80为缺水警告。所有居民仍具有投票资格，不以饥饿/休息状态剥夺选票。

## 非功能需求
业务函数不访问DOM、时钟、网络；只使用传入PRNG状态。日结算不变量必须可独立测试。性能验收并入M1目标，不声称已测。

## 边界与异常
| 场景 | 预期行为 | 对应AC |
| --- | --- | --- |
| 精力19/20 | 19休息，20可工作 | M2-AC-01 |
| 公库不足工资 | 支付可用部分，WAGE_SHORTFALL | M2-AC-01 |
| 饥饿49/50、余额1/2、粮食0/1 | 严格按AC消费，不负数 | M2-AC-02 |
| 清水0 | WATER_OUT_OF_STOCK，不减需求 | M2-AC-02 |
| 关系99/100、广场关闭/无配对 | 截断100或明确跳过 | M2-AC-03 |
| 需求100、30天 | 截断、守恒、同输入同输出 | M2-AC-04 |

## Non-Goals
不做动态价格、贷款、死亡、自由职业编辑或大模型对话；不声称这些简化规则具有社会预测效度。
