```text
问题：公库只有 119 镇币时，创建者执行一个已通过、成本为 120 镇币的维修水井议案，系统应该发生什么？为什么？
```

## 3. AI 回答摘要

ChatGPT 给出的核心结论是：

1. 系统重新读取公库后应发现 119 镇币不足以支付 120 镇币成本。
2. 应拒绝本次执行并返回 `INSUFFICIENT_TREASURY`。
3. 应提示还差 1 镇币。
4. 公库仍为 119 镇币，清水库存和社区信任不变。
5. 议案状态仍为 `APPROVED`。
6. 不应生成成功执行事件，也不能发生部分扣款或资源增加。
7. 原因来自 AC-07 和 FR-05：执行前必须校验资金，执行失败必须保持业务状态不变并满足原子性。

最终结论为：

> 由于 119 小于 120，系统应返回 `INSUFFICIENT_TREASURY`，拒绝本次执行，并保留议案的 `APPROVED` 状态及所有原有资源数据。

## 5. 发现的偏差

AI 对业务结果的理解正确，但回答只说明“不生成成功执行事件”，没有明确错误尝试本身是否进入时间线。

检查跨文档规则后发现：

- M4 原文要求“任何一步失败时全部状态不变”。
- M5 要求用户操作和异常拒绝都产生事件。
- 两句话会被不同实现者理解为“完全不记录”或“只记录失败事件”。

这是规格歧义，不是 AI 自行扩展功能。

## 6. 规格修订

已修改以下内容：

- M4 的 AC-07 明确执行失败时追加 `PROPOSAL_EXECUTION_FAILED`。
- M4 的 FR-05 明确失败只改变审计事件，不改变公库、清水、信任或议案业务状态。
- M5 明确快照导入失败只追加 `SNAPSHOT_IMPORT_FAILED`，不留下部分恢复状态。
- M1 和 M3 同步采用“业务状态不变，追加失败事件”的规则。
