# 地图扩展与资源循环

> 本页记录地图版本2。当前版本3已扩展至5个分区、21个地点、15种商品，增量规则见[街区扩展](district-expansion.md)。

日期：2026-11-19。当前本地版本，保留已有世界；本轮未提交GitHub。

## 地图与用途

| 区域 | 地点与主要活动 |
| --- | --- |
| 中心街区 | 原有住宅、农场、工坊、面包房、集市、事务所、广场；工坊新增工具制作 |
| 东岸原野 | 迷雾森林伐木、河畔果园采果、山脚矿洞采矿、钓鱼台钓鱼与烤鱼、草药园采药与泡茶 |
| 南部田园 | 南岸营地野餐；耕地、花草和帐篷作为场景装饰，不额外生成隐藏产出 |

共有13个可选择地点。两座桥连接东西岸，水面不可通行，角色按服务端路线过桥。旧版画在水上的建筑移到陆地，去掉重复矿洞、棚屋和温室。场景保持原创高清Canvas画面，没有引入Smallville素材。

地图顶部分区按钮切换中心街区、东岸原野、南部田园和全镇；拖拽、小地图定位与居民跟随继续可用。小地图覆盖1440×1024逻辑活动区，显示建筑、道路、河流、桥、居民、所选居民的实际路线及相机范围。场景外围为装饰区，不暗示全部可探索。

地点面板显示真实配方、精力消耗、工具加成和当前原料不足提示。预计步行时间由只读`GET /api/me/route?place=...`按当前服务端位置和路线计算；它是估计值，等待下个tick、后续接管或路径变化会改变实际耗时。行动仍在到达后检查原料/精力并结算，查看地点不会立即扣款或生产。

## 资源循环规则

| 行动 | 投入 | 产出/效果 | 精力消耗 |
| --- | --- | --- | --- |
| 采集水果 | 无 | 水果2 | 7 |
| 吃水果 | 水果1 | 饥饿-20 | 0 |
| 河边钓鱼 | 无 | 鲜鱼1 | 8 |
| 制作烤鱼餐 | 鲜鱼1、木材1 | 烤鱼餐1 | 4 |
| 享用烤鱼餐 | 烤鱼餐1 | 饥饿-45、精力+8 | 0 |
| 采集草药 | 无 | 草药2 | 7 |
| 冲泡草药茶 | 草药2 | 精力+18 | 0 |
| 开采矿石 | 无 | 矿石2 | 13 |
| 打造工具 | 矿石2、木材2 | 工具1 | 8 |
| 森林伐木 | 无 | 木材3 | 11 |
| 营地野餐 | 水果2 | 饥饿-30、精力+12 | 0 |

携带工具执行采矿/伐木时自动消耗1工具，额外得到2份对应物资；面板明确显示此规则。工具是单次耗材，不是耐久装备。满包检查按投入消耗后的净容量计算；任何原料、容量或精力校验失败都不扣材料，不消耗工具，不发成长奖励。属性限制在0–100，资金规则不变。新动作获得少量成长值，原六项徽章条件不变。

市场和订单支持九种商品（谷物、面包、木材、水果、鲜鱼、矿石、草药、烤鱼餐、工具）。原有面包配方仍为2谷物→3面包，没有声称已实现面粉生产链。烤鱼餐与工具在新世界初始市场为0，需要生产或玩家订单流通；旧世界新增物资仅补0，绝不补发资产。

手工计划可加入新动作，托管可选择采集、钓鱼、伐木、采矿、采药、烤鱼或打造。烤鱼和打造缺原料时，备用规则会先钓鱼/制作木材/采矿；饥饿时优先吃现有烤鱼餐、水果或面包，精力不足且有草药时泡茶。部分NPC上午前往东岸采集、伐木、采药，午间社交和夜间休息规则保留。该调度完全是本地确定性规则，不调用模型。

## 工程边界

- `shared/world-map.json`：唯一几何来源，包含场景边界、活动网格、河流、桥、道路、地点、建筑和碰撞体。
- `backend/app/world_map.py`与`frontend/src/game/world-layout.ts`读取同一文件；Docker两个构建阶段均复制shared目录。
- `game/art/vegetation.ts`、`water.ts`、`regions.ts`分别处理植被、水系与区域细节，`terrain.ts`组合地形，建筑继续独立绘制。
- `domain/recipes.py`定义投入产出、食品效果和工具增益；`catalog`发布规则，`domain/actions`在原事务内验证并结算，Vue不计算奖励。
- `/api/me/route`只读，既不接管居民，也不写revision；估算与行动使用同一寻路函数。
- `map_version=2`迁移：保留全部资产、个人模式、待执行计划与世界时钟；只有站在新障碍/水面上的居民移到最近合法网格，已有行程按新入口重算。迁移幂等，已有完整计划不会清空。

## 验证与限制

新增测试覆盖所有新增地点过桥与准确到达、桥外水面拒绝、建筑/入口几何一致、老世界位置与路线迁移、全部生产配方、工具增益与失败不扣款、食品属性上限、只读路线接口、新商品订单和新托管动作。

Chrome额外跑通真实果园采果/食用以及完整工具与烤鱼链；在1440×900/DPR2和1280×720/DPR1检查四个分区和地点面板。独立SQLite测试库使用0.15秒tick以缩短验收时间，日常本地世界仍为2秒tick。没有使用真实模型或虚构居民行为证据。

当前仍是单世界场景，分区导航是相机切换，并非多个服务器地图。没有增加天气产量、自由建造、工具耐久、地块所有权或资源枯竭/再生系统。


## 行动与配方体验补充

- 地图底部展示本人当前目的地、动作和预计耗时。预计值由当前权威坐标沿剩余路径求和，以catalog公布的每tick移动距离和tick_seconds换算，非逐秒倒计时；断线显示等待同步。停止行动切换为本人控制、清空当前路径/任务并更新状态为“等待新安排”，保留全部未执行计划与资产。
- 待执行计划可折叠查看，并进入AI分身页面编辑；本轮不自动覆盖或追加计划。背包直接使用面包、水果和烤鱼餐；操作会接管角色，原料不足按钮禁用。
- 生活手册新增“配方图鉴”，分为制作、采集、饮食与恢复，可搜索动作、产物和地点。原料显示“持有/需要”，不足时提供实际产地入口，生产链和恢复数值均来自catalog。地点跳转只打开详情，不会立即开始消耗。
- 人物动画按旧路线上实际走到的坐标恢复路段，不再用新旧路径长度差猜测步数。换目的地或停止时不会误走旧路线的剩余路点；无法与旧路线对应的权威位置变化直接校正，避免穿墙动画。
- 相机按固定区域尺寸重算fit，保留缩放倍数和中心锚点；扩大地图时边界会钳制可见中心，恢复后回到原视野。拖拽、缩放、导览或跟随会更新锚点。连续切换三次的往返验证覆盖中心与可见宽度，避免累计漂移。

组件、纯路径函数和样式分别位于TownJourney.vue、RecipeBook.vue、game/motion.ts与styles/gameplay.css。没有新增数据库字段或修改已有生产规则。
