# v2 Spec：共享数字分身契约

日期：2026-11-20；状态：本地实现基线。课程原版五模块 Spec 保留在 `spec/`，不直接约束本版本的新技术和实时世界。

## 摘要

六名固定成员和六名系统居民共用一个服务端世界。每名玩家只控制自己的居民，在线可用个人模型生成计划；离线不续发模型请求，但已有计划和规则继续。完整产品动机见[产品设计](product-design.md)，模块边界见[架构](architecture.md)。

## 用户故事与功能要求

| 编号 | 用户故事 | 实现位置 |
| --- | --- | --- |
| V2-US-01 | 成员登录自己的身份，与同伴同时在线 | api/auth、api/realtime、stores/town |
| V2-US-02 | 观察并控制自己居民的路线、状态和生计 | domain/actions、pathfinding、game/TownScene |
| V2-US-03 | 通过市场、采购和建设进行合作 | domain/orders、api/orders、ProjectView |
| V2-US-04 | 自己选择模型，让计划在离线时继续执行 | ai、domain/scheduler、AgentView |
| V2-US-05 | 给成员留言并追踪生活结果 | api/messages、api/world、ReportView |
| V2-US-06 | 保存并恢复个人安排，不覆盖他人进度 | api/archives、runtime、ArchivesView |
| V2-US-07 | 查看成长目标和真实完成记录，逐步参与小镇生活 | domain/progression、TownJournal、useProgress |
| V2-US-08 | 清楚观察场景并与选中的邻居交流 | game、TownMap、domain/actions |

## 验收标准（Given/When/Then）

### V2-AC-01 固定身份和同时在线（V2-US-01）

```gherkin
Given 六个固定成员使用各自用户名和同名密码
When 在六个独立浏览器上下文登录并连接世界
Then 六人进入同一小镇，在线人数显示6，世界内有12个居民
```

### V2-AC-02 角色控制归属（V2-US-01）

```gherkin
Given 王崛已经登录
When 提交行动并额外传入其他角色ID
Then 请求被拒绝，不能越过会话归属控制其他居民
```

### V2-AC-03 到达后结算（V2-US-02）

```gherkin
Given 居民在农场以外，背包和精力足够
When 安排采收并推进服务器时钟
Then 到达之前没有谷物奖励，到达后增加3份谷物并同步到其他玩家
```

### V2-AC-04 失败与守恒（V2-US-02）

```gherkin
Given 一个有效世界
When 命令不合法或到达时所需资产不足
Then 不发生部分扣款或增发资金，拒绝命令不修改世界，行动失败记入记录
```

### V2-AC-05 订单唯一交付（V2-US-03）

```gherkin
Given 买家发布采购并托管足额资金，两名卖家有物资
When 两名卖家同时交付同一订单
Then 只有一名卖家获得报酬且仅转移一次物资，另一请求被拒绝
```

取消由买家本人发起。订单在 144 tick 后到期，未交付资金一次性退回。

### V2-AC-06 共建效果（V2-US-03）

```gherkin
Given 仓库尚未完成
When 小组累计捐建40份木材和400镇币
Then 仓库落成且所有居民容量增至60份，重复或超出目标的捐建被拒绝
```

### V2-AC-07 模型计划（V2-US-04）

```gherkin
Given 玩家保持在线且配置了兼容模型接口
When 主动发起一次规划且模型返回合法JSON
Then LangGraph校验最多八个允许动作后保存本人计划，玩家决定是否启用执行
```

本条目前以完整图流程 mock 和 HTTP MockTransport 验证；尚无真实服务商联调结果。错误格式、未知动作和越界数量不写入计划。

### V2-AC-08 离线不续发请求（V2-US-04）

```gherkin
Given 玩家已经启用计划与规则托管
When 最后一个有效连接退出或租约失效
Then 本地待处理模型任务被取消，不再新发起模型调用，已有计划与备用规则继续
```

心跳间隔 5 秒、租约 20 秒；已经发给第三方的请求无法撤销其已发生的用量。模式为本人控制时完成退出前已有单次行动后等待，不擅自开启托管。

### V2-AC-09 自主预算（V2-US-04）

```gherkin
Given 玩家配置保留余额和每日自主支出上限
When 托管尝试购买或捐款
Then 必须同时满足两项约束，否则不扣款并留下失败原因
```

手动操作是玩家的直接决定，不套用自主预算。每日支出在模拟午夜重置。

### V2-AC-10 私信和记录（V2-US-05）

```gherkin
Given 王崛给张果发送一条留言
When 张果与第三名成员分别查看留言页
Then 张果看到留言，第三名成员看不到双方私信，世界事件可独立筛选和分页
```

### V2-AC-11 持久化与个人恢复（V2-US-06）

```gherkin
Given 世界已有资产、个人计划、规则及个人归档
When 服务器重新启动，或本人恢复个人归档
Then 重启保留已提交状态，恢复仅改本人的计划与规则，不回滚共享资产和他人进度
```

个人归档上限 20 份，支持查看、JSON 导出与删除。其他账号不能读取或恢复本人的归档。

### V2-AC-12 回归摘要（V2-US-05）

```gherkin
Given 玩家退出时记录了tick、余额与完成行动数
When 世界继续运行且玩家再次登录
Then 展示离开后的完成次数、余额变化和最多八条本人记录，不为摘要调用模型
```

### V2-AC-13 高清场景与地图控制（V2-US-08）

```gherkin
Given 玩家在1440×900的2倍像素密度屏幕或1280×720的普通屏幕进入小镇
When 查看场景并操作导览、小地图、角色跟随、缩放、扩大和恢复
Then 画布像素宽高匹配显示尺寸乘像素密度，地图控件正常，无横向溢出和页面脚本错误
```

逻辑坐标由服务端地点与寻路边界管理，美术在3倍采样画布绘制；设施标签以高清文本绘制，保持可读尺寸。路线是服务端路径预览；拖拽或小地图定位退出角色跟随。环境动态与昼夜可关闭。

### V2-AC-14 成长目标与兼容旧世界（V2-US-07）

```gherkin
Given 玩家有个人成长记录，或已有世界尚无成长字段
When 成功完成生产、交易、交流、捐建或交付，以及再次读取或恢复个人归档
Then 成功行动累计计数和成长值，六项徽章各最多发放一次，失败无奖励，恢复计划不回退进度，旧世界资产与计划保留
```

徽章对应6份谷物、6份烘焙面包、3笔市场买卖、2次邻里交流、2份木材捐建、1笔向玩家交付的订单。每项首次达成增加20成长值；行动成长值由领域常量表定义，100成长值升一级，目前等级为荣誉展示，不改变资产或能力。旧数据的细分历史不能推断，新增计数从升级后开始。仓库已落成且尚未达成捐建徽章时显示本期建设已结束，不伪造完成。

### V2-AC-15 指定居民交流（V2-US-08）

```gherkin
Given 玩家选择另一名成员或系统居民
When 安排前去交流并到达目标居民附近
Then 到达后双方熟悉度各增加5且上限100，只控制本人；目标不存在、为本人或已离开范围时不发放交流奖励
```

目标参数为social动作的target_id；寻路前往发起时对方位置，到达后重新检查曼哈顿距离小于100。此功能是确定性邻里互动，不调用模型，不生成虚构对话。

### V2-AC-16 慢连接隔离与增量重同步（V2-US-01）

```gherkin
Given 多名玩家使用增量协议连接同一世界，其中一个连接发送受阻
When 服务端持续提交行动，或客户端收到基线不连续的更新
Then 健康连接和事务继续推进，待发送状态有界，客户端请求并应用新的全量状态
```

每连接最多一条待发状态，超时断开慢连接；增量基于该连接最后成功发送的版本，允许跳过中间revision，但base_revision必须匹配。保留旧协议全量兼容。世界事务在工作线程执行，取消请求必须等提交结束才释放世界锁。

### V2-AC-17 网络故障可恢复（V2-US-01）

```gherkin
Given 后端不可达、响应体停滞或WebSocket连接关闭
When 玩家进入应用或执行请求
Then 有限超时后显示中文反馈和启动重试入口，连接指数退避重连，写请求不自动重复提交
```

普通请求默认12秒，模型请求40秒；模型步骤服务端总时限32秒。事件筛选取消旧请求，退出清除个人功能状态，过期响应不能覆写新会话。

### V2-AC-18 资金循环与NPC等待（V2-US-02）

```gherkin
Given 国库不足、背包已满或附近没有其他居民
When 托管选择下一行动并跨过模拟午夜
Then 不安排确定无法支付的出售或无目标社交，等待后重试，维护金从居民结余转入国库且总资金守恒
```

维护金默认为超过max(100镇币,个人保留余额)部分的5%，向上取整；不计入玩家自主购买预算，不侵入保留余额。NPC06点起床、12至14点附近社交、21点起夜间休息，饥饿优先处理。饥饿达到80时休息恢复12精力，其余恢复25；默认等待12tick。参数在game.json，规则页面可查看维护金，不承诺任意策略下经济永不停止。

### V2-AC-19 真实报表采样（V2-US-05）

```gherkin
Given 世界运行并已有至少两个经济采样点
When 玩家打开生活记录或刷新报表并切换趋势指标
Then 显示真实的公共资金、居民持币或累计交易曲线，以及当前物资分布和本人关系，缺少历史时显示等待而不编造
```

每6tick在独立表采样，保留最近240点，同tick更新而不重复插入；历史不进入每次世界广播。资源分布为当前快照，趋势为最近刷新时的历史采样，界面标出采样时间。

### V2-AC-20 地图扩展与桥梁通行（V2-US-08）

```gherkin
Given 地图包含五个分区、21个地点与三座跨河桥
When 切换分区、查看小地图、请求路线并安排跨河行动
Then 地形与服务端入口来自同一份定义，水面只能经桥通行，路线预览不改世界，人物到达有效入口后才结算
```

旧世界升级保留资产、模式和计划，仅修正新障碍内的位置并重算当前路线；地图迁移重复运行不再变更。详见[地图扩展](map-expansion.md)。当前行动栏根据服务端剩余路径和移动速度显示预计耗时；停止只清除当前行程，保留待执行计划。改道不得按旧路径长度误播路点；地图扩大/恢复保留缩放比例和相机锚点，边缘允许边界钳制。

### V2-AC-21 新资源的生产与使用（V2-US-02、V2-US-03、V2-US-04）

```gherkin
Given 玩家有新物资或可前往相应设施收集
When 制作工具、采矿、烤鱼、食用、泡茶或野餐，以及用新商品发布订单和安排托管
Then 按目录公布的投入产出在服务端原子结算，失败不消耗工具或原料，食品属性不越界，离线规则不新增模型调用
```

商品总数15；工具用于一次采矿/伐木额外获得2份产物。具体配方与恢复数值见[地图扩展](map-expansion.md)及[街区扩展](district-expansion.md)，市场、订单、手工计划和模型上下文共用目录。生活手册提供目录驱动的配方图鉴、材料持有量和来源入口；背包可直接使用现有食品，数量不足不可点击。所有产出仍由服务端结算。

### V2-AC-22 有限计划与队列编辑（V2-US-02、V2-US-04）

```gherkin
Given 玩家拥有最多8步待执行计划，并可从地点或配方追加行动
When 调整队列并选择仅执行本轮，或另一会话在编辑期间改变队列
Then 依次结算后自动停止，失败暂停后续步骤且不扣失败原料；过期编辑被拒绝，离线继续执行已有步骤且不调用模型
```

追加不打断当前行动，不自动切换控制模式。仅执行本轮失败后，失败步骤已消耗一次尝试，不自动重试；尚未执行的步骤保留。长期规则托管仍在队列结束后运行备用规则。最多8步指待执行队列，不含正在行走的当前任务。详见[行动队列](action-queue.md)。

### V2-AC-23 新街区生产与社区交付（V2-US-02、V2-US-03）

```gherkin
Given 居民可前往菜园、蜂场、亚麻田、织坊、家具坊、厨房、茶舍与交付站
When 通过有限计划制作家具或浓汤并前往交付，或重复交付、超每日额度、缺料、预算不足
Then 只有实际到站且条件满足才消耗完整物资并从公共资金支付报酬，每种每日一次、每日最多三种，失败不改资产与额度
```

新增物资初始为0，累计交付数据由成功结算产生并实时同步；不把公共物资交付计为玩家间的合作订单。离线执行已有计划与规则，不新增模型请求。规则、配方和地图范围见[街区扩展](district-expansion.md)。

## 非功能要求

- 前端业务、场景、模型调用、领域结算与持久化分层；领域层不得调用网络。
- 面向桌面 1440×900 和 1280×720，地图之外以白底、黑线和少量贴纸色为主；窄屏不作为本次验收目标。
- 单进程事务原子性；资产使用整数，余额、物资与库存不为负，现金、公库、托管资金之和守恒。
- 每 2 秒推进一次，10 模拟分钟/tick；广播权威状态，不把客户端动画作为结算依据。
- 参数、身份归属与业务失败可反馈中文原因；模型密钥不返回浏览器。
- 用量只有服务商返回时才显示数字；没有返回用量则明确显示未报告。

## 边界与异常

| 场景 | 处理 | 对应验收 |
| --- | --- | --- |
| 资源被其他玩家先买走 | 到达后重新检查，失败无部分扣款 | V2-AC-03、04 |
| 两人同时交付 | 世界锁与事务保证一次成功 | V2-AC-05 |
| 背包满、精力不足 | 失败原因可见；托管精力低时先休息 | V2-AC-04、09 |
| 模型超时/非法动作 | 原计划保留，界面提示 | V2-AC-07 |
| 退出后模型迟到返回 | 再次检查在线，不应用结果 | V2-AC-08 |
| 多标签页 | 最后一个有效连接离开才离线 | V2-AC-08 |
| 归档来自其他账号 | 404，不泄露他人资料 | V2-AC-11 |
| 服务器停止 | 世界停止推进，重启接续，无时间追算 | V2-AC-11 |

## Non-Goals

当前不承诺完整人格模拟、无限自主模型循环、AI 自由对话、AI 自动接受订单或发送留言、店铺经营、自由地图、多世界、动态物价、跨进程水平扩展、真实社会预测。未部署云端，不把本地服务端存档称为已经上线的云服务。

### V2-AC-24 后端可恢复与无损结构升级（V2-US-01）

```gherkin
Given 已有六名成员的共享世界，或新建空数据库
When 升级数据库、重复启动，或注入数据库与世界时钟故障
Then 迁移保留旧数据且可重复执行，错误结构拒绝接管；就绪检查在故障时返回503、恢复后返回200，进程存活检查独立可用
```

结构升级采用 Alembic；已有表的必需列和主键必须兼容，索引冲突不静默忽略。真实存档先一致性备份，再对副本做行摘要、模型一致性与完整性核验。时钟单轮连接校验或事务失败不会终止主循环；就绪同时检查数据库、任务状态和最后成功 tick 的时效。错误响应含 detail、code 和 request_id；参数校验不回显用户提交内容。阻塞事务在取消后完成协调才释放锁，不能将“取消等待”当作“事务已停止”。
