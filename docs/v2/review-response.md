## 报告中需要校正的判断

- 公共工作是从有限国库向居民转账，原代码也检查资金守恒，不是“印钱”。问题是资金回流不足；维护金改善循环，但在全体设高保留余额、停止消费等极端策略下仍可能停滞，不能承诺任何策略都自动繁荣。
- WebSocket 原实现并非后缀匹配。本轮将来源判断集中为解析后精确比较host/port，加入域名伪装等测试，不把不存在的漏洞写成已修复漏洞。
- LLM JSON解析原来已经位于try内；实际问题是部分ValueError直接暴露解析细节。本轮统一解析错误文案与记录状态。
- 当前已有关系数值、个人成长、离线固定规则、调用间隔、模型响应长度限制、依赖锁和全地点对寻路测试；并非报告所称完全没有这些内容。
- JSON引用和输入“消毒”不能保证消除提示注入。用户简介、目标和留言仍按不可信上下文发送，核心约束依赖服务端动作白名单、数量上限、本人归属与在线检查。本轮没有把角色输入修改为不可用，也没有声称模型绝不受诱导。

## 明确延后

1. **Redis、多worker、AOI、JSONB/实体分片**：当前仍是12居民、单世界、单worker。已减少每连接重复读库和网络阻塞，但世界仍整块JSON更新，个性化快照仍有复制成本。先测量更大世界的成本，再设计单一时钟所有权、事务顺序、跨进程会话取消和消息总线，不能直接增加worker。
2. **小麦→面粉→面包、工具/升级链、动态价格、部分订单成交、关系折扣、天气影响、季节与新建筑**：需明确配方、价格和资金边界，先扩充玩法Spec再实施。本轮不把静态weather/season字段称为动态天气系统。
3. **师徒、赛季、自由建造、默认NPC大模型**：未实现。NPC采用固定日程与状态规则，不耗模型token；玩家仍需主动请求AI。继续保持离线不新调用模型。
4. **移动端、音效、完整无障碍、完整新手教程、全局快捷键**：按已有要求优先桌面；生活手册/地图导览已存在，不等于完整教程。
5. **安全部署加固与账户策略**：保留六人同名账号密码，未更换认证方式或增加用户未要求的登录障碍。公开部署前的容器运行身份、HTTPS/cookie等仍需独立验收。
6. **覆盖率门槛、真实PostgreSQL恢复、真实模型服务、多机压力**：没有虚报。新增测试聚焦可复现业务和故障；未以测试数量代替覆盖率。
