# 团队协作指南

## 文档维护

README 作为入口，只保留项目定位、范围、状态和导航。业务需求写入 `spec/`；技术取舍写入 `adr/`；分阶段工作写入 `plans/`；协作和参考资料约定放在 `docs/`。

## Issue 与 Pull Request

每个 Issue 描述用户/开发背景、目标、验收条件和影响文档。Pull Request 关联 Issue，列出修改摘要、验证方式、受影响需求或 ADR，并说明尚未解决的限制。需求或数据模型改变时，代码与文档在同一变更中更新。

## 验证建议

- 规则模块使用固定输入验证资源、余额、容量和投票等确定性结算。
- 模型输出验证结构、动作许可和字段范围，并覆盖超时、错误响应与不可解析输出。
- 演示配置保存随机种子和规则版本，记录运行日志与快照。
- 页面验证至少覆盖创建/载入、推进/暂停、居民详情、议题结果和事件时间线。

## 发布前检查

确认没有密钥或未授权个人数据；README 的功能状态与实际实现一致；演示配置可被其他组员载入；验收记录包含可复现输入和结果。
