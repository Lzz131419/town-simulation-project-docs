# 阶段计划：愿景到MVP1

## 1. 阶段目标
保留初始项目“小镇生活与公共决策可观察、可复盘”的方向，先交付固定场景闭环。初始PDF的六周实施建议是相对开发阶段；课程06–09是上下文/规格/架构/计划四次交付，二者不按日历机械重合。

## 2. 课程推进
| 阶段 | 交付 | 退出条件 |
| --- | --- | --- |
| 第6周 INFORM | context、规则、标准目录、看板与文档PR演练 | 文档可核对；线上流程有真实证据 |
| 第7周 SPEC | scope、五模块Spec、冷启动 | 正常/边界/异常可验收；独立会话记录 |
| 第8周 ADR | architecture、两份ADR、依赖风险、spike计划 | 契约一致；团队人工接受基线 |
| 第9周 PLAN | 12任务、分支表、PR门禁、看板 | 每任务有AC、负责人、依赖；线上卡片同步 |
| 第10–11周 BUILD/VERIFY | 任务PR、测试、MVP1演示 | 按DEMO-01真实运行并评审 |
| 第12–14周 | MVP2候选与维护 | MVP1通过后另定范围 |
| 第15–16周 | 联调、答辩与复盘 | 证据、局限与个人答辩准备 |

## 3. 原构想保留和延后
MVP1：生产、市场、社交、娱乐、固定公共决策、1名授权人物、30日运行、短缺、快照。MVP2候选：多模板、更多人物、更多设施、自由议题、服务端模型辅助；MVP3候选：历史比较与玩家居民视角。后续只有方向，不提前拆入MVP1任务或承诺日期。

## 4. 演示与工作量
[DEMO-01](../docs/test/demo-acceptance.md)给出唯一验收顺序；[Plan](mvp1-plan.md)给出人日和关键路径。预计27人日、关键路径15工作日，加评审/返工缓冲后再按课表排期；不是既成完成率。

## 5. 当前状态
本轮正在交付文档与限定机制探针；正式功能、线上看板更新、人工PR评审分别核验，不把文档完成等同于整个项目完成。
