# ADR-001：MVP1 运行时与状态持久化

- 状态：提议（本轮推荐方案；未记录人工接受）。
- 日期：2026-11-18；拟评审：张果、王崛；实际评审签名：尚未发生。

## 背景
课程第6–9周要求先确定边界与契约，第10周再开发。已有单文件HTML探针能展示方向，但其localStorage、固定投票与不完整随机状态不能作为正式架构。MVP1只有31人、30天、单机观察，不依赖模型。

## 决策
推荐HTML/CSS + JavaScript ES modules，规则与UI拆开，浏览器内存存一个world，JSON显式导入导出；Node.js 22+内置test用于正式规则测试。通过本地静态HTTP服务加载，不采用file://加载ES modules。

## 备选方案
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A 原生模块+内存+JSON（推荐） | 无运行时依赖，规则可单测，离线复现简单 | 需自管页面状态，关闭前必须导出 |
| B React/Vue+浏览器数据库 | 组件生态、存储容量更强 | 构建/依赖/迁移增多；本版用户价值不足 |
| C FastAPI+SQLite/PostgreSQL+前端 | 多用户与模型代理扩展方便 | 接口、部署、并发、账号边界均扩大 |
| D 延续单文件探针 | 起步快 | 模块耦合、无法稳定并行评审、已知规则缺失 |

## 取舍与 trade-off
选择A作为提议：满足当前可验收范围而保留清晰模块边界；接受手工保存与单机限制。B/C可在后续在线或智能体需求确认后重新评估，不宣称未来无成本迁移。D只作为历史演示保留。

## 后果与影响文件
影响context、五模块Spec、architecture、计划文件白名单。无HTTP业务API；接口必须用Result，不能照搬模板201/409。无需引入数据库事务或分布式锁；原子性由ADR-002定义。

## 待验证与退出条件
SP-01验证副本原子提交与PRNG恢复；SP-02计划验证浏览器表单、模块加载、快照和性能。若31人30日文件超5MiB或响应达不到目标，先测量瓶颈，再提新ADR讨论分段存储，不静默丢事件。
