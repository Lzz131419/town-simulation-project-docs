# ADR-003：以服务端权威世界重建多人数字分身

- 日期：2026-11-19
- 状态：根据用户明确技术与产品要求已在本地实施；尚未提交远程，未虚构小组签字。
- 替代范围：ADR-001 中仅浏览器、无框架/后端/数据库/模型的约束，只对 v1 保持历史意义；ADR-002 的原子性思想保留，单机完整世界恢复语义不适用于共享世界个人恢复。

## 背景

用户明确要求六人同时登录同一世界、各自控制居民与配置模型，退出后继续已有规则但不消耗新的模型调用；并要求 Vue、游戏引擎、FastAPI、数据库、Agent 框架及账号存档。浏览器内存单机方案无法提供唯一事实和共同资产。

## 决策

使用 Vue 3 / TypeScript 负责界面，Phaser 3 负责 2D 场景；FastAPI 提供 HTTP 与 WebSocket，SQLAlchemy 管理 SQLite 本地持久化，LangGraph 组织有边界的规划流程。提供 PostgreSQL / Docker 候选部署配方，但外部部署另行验收。

世界命令与时钟通过一个运行时互斥入口，在副本上计算、不变量通过后原子提交。后端单 worker；前端动画不参与结算。离线规则执行与模型调用完全分开；模型只生成计划，玩家决定执行。个人归档只恢复本人计划与规则，不能覆盖共享资产。

代码按页面、功能状态、场景、接口、应用服务、领域、模型适配和存储拆分。保留 v1 与原课程文档，通过新版 README/context 指明当前入口。

## 备选

| 方案 | 取舍 |
| --- | --- |
| 继续单机原生 JS | 无法满足同时在线与服务端持久化 |
| Unity 客户端 | 当前桌面网页 2D 场景无需额外客户端与大型工具链；Phaser 易接入 Vue |
| 只用模型自然语言控制世界 | 难以校验资产、预算与重复支付；保留确定性规则执行 |
| 一开始多进程/分布式世界 | 六人规模先用单 worker，明确扩展边界，避免未验证的一致性复杂度 |

## 后果

增加 Python/Node 依赖、运行进程与数据库运维；启动不再是单个静态页面。单进程和 JSON 世界存储适合当前小组规模，未来多世界与扩容需独立设计。真实模型、PostgreSQL、部署和数据迁移仍需实际验收。
